#  **Telegram Bot for File Conversion & Subscriptions**

Асинхронный Telegram-бот для конвертации файлов с продвинутой системой подписок, ролевой моделью и аналитикой. Проект демонстрирует навыки проектирования реляционных баз данных, асинхронного программирования и создания масштабируемой backend-архитектуры.

## **🎯 О проекте**
**Этот проект является образовательным и имеет множество недостатков и нуждается во множестве доработок** 

*Бот позволяет пользователям конвертировать файлы (изображения, документы, архивы) прямо в Telegram. Помимо базовой функциональности, внутри реализована полноценная бизнес-логика: система тарифов (Free/Premium), daily rate-limiting, история платежей и админ-панель для управления пользователями и сбора обратной связи.*

## 🌟 Ключевые возможности

### 👤 Для пользователей:
- 📤 Загрузка и конвертация файлов в популярных форматах.
- 📊 Прозрачная система лимитов (5 конвертаций/день для Free).
- 💳 Оформление и отслеживание статуса Premium-подписки.
- 🎫 Создание тикета и просмотр ответов поддержки прямо в боте.

### 🛡 Для администраторов:
- 👥 Управление пользователями и назначение ролей (Admin / Super Admin).
- 📈 Просмотр статистики и истории действий (журнал аудита).
-  Подтверждение платежей и ручная активация подписок.
- 🎫 Просмотр тикетов, ответы пользователям и закрытие обращений из админ-панели.

## 🏗 Архитектура и Стек

*Проект построен по принципам **Separation of Concerns** (разделение ответственности) с использованием современных асинхронных подходов.*

### 🛠 Технологический стек:
- **Язык:** Python 3.13
- **Фреймворк:** aiogram 3.x (Router-based архитектура, FSM, Middleware)
- **База данных:** SQLite (асинхронный драйвер `aiosqlite`)
- **Асинхронность:** `asyncio` (неблокирующий I/O для БД и файловой системы)
- **Конфигурация:** `python-dotenv` (безопасное хранение токенов)

### 📂 Структура модулей:
```Структура модулей:
ConverterFileBot/
├── app.py                  # Точка входа, инициализация Dispatcher и graceful shutdown
├── handlers/               # Роутеры для обработки команд (user, admin, formats)
├── kbds/                   # Само построение клавиатуры как для админов, так и для обычных пользователей
├── middlewares/            # Глобальное логирование входящих апдейтов
├── data_base/              # Слой абстракции данных (async SQL queries)
├── filters/                # Кастомные фильтры aiogram
├── converter_service.py    # Бизнес-логика конвертации файлов
├── init_super_admin.py     # Инициализация главного админа (для этого необходимо узнать свой ID и вставить его в код) -- это необходимо, чтобы не пришлось делать это вручную через базу данных
├── converter.py            # Конвертация файлов при помощи сервисов
├── .env                    # Окружающая среда
├── requirements            # Библиотеки 
└── utils.py                # Вспомогательные утилиты

```

## 🗄 Проектирование Базы Данных (Data Engineering)
Ядро проекта — нормализованная реляционная база данных, спроектированная с учетом целостности и аналитики.
### Схема данных (8 связанных таблиц):

- **users** — профили, роли, дата регистрации.
- **user_actions** — журнал аудита (Data logging для аналитики поведения).
- **subscriptions** — тарифы, даты начала и окончания подписки.
- **daily_conversion_counters** — счетчики для реализации rate-limiting.
- **payments / payment_history** — финансовые транзакции и их статусы.
- **feedbacks** — обращения из старой формы обратной связи.
- **support_tickets** — тикеты пользователей, ответы администраторов и статусы обработки.
- **last_bot_message** — оптимизация UI (избегание спама сообщениями).
- **super_admin** — таблица для разграничения прав высшего уровня.

### Реализованные SQL-паттерны:

- Ссылочная целостность: Использование FOREIGN KEY и каскадных связей.
- Сложные выборки: JOIN таблиц (например, subscriptions + users для выгрузки отчетов админу).
- Агрегация и аналитика: COUNT, GROUP BY, ORDER BY для подсчета метрик.
- UPSERT (Atomic operations): Использование ON CONFLICT DO UPDATE для атомарного инкремента счетчиков конвертаций без гонок данных (Race Conditions).
- Индексация: Создание индексов (CREATE INDEX) для ускорения поиска по ID и статусам.
- Надежность: Обработка исключений на уровне БД с логированием ошибок в файлы без остановки основного процесса.

### Пример SQL-запроса из проекта (Аналитика подписок):
```
SELECT s.user_id, u.username, u.first_name, s.plan_type, s.is_active, s.end_date
FROM subscriptions s
JOIN users u ON s.user_id = u.user_id
WHERE s.is_active = 1
ORDER BY s.end_date ASC;
```


## **🚀 Установка и локальный запуск**
### Клонируйте репозиторий:
```
   git clone https://github.com/shmepas/ConverterFileBot
   cd ConverterFileBot
```

### Создайте виртуальное окружение и установите зависимости:

```
   python -m venv venv
   source venv/bin/activate  # Для Windows: venv\Scripts\activate
   pip install -r requirements.txt
```

### **Настройте переменные окружения:**
### Откройте файл .env в корневой папке и измените:

```
   TOKEN=ваш_токен_от_BotFather
   SUPER_ADMIN_ID=ваш_telegram_user_id
```

### Запустите бота:

```
    python app.py
```

## 📊 Почему это важно для Data Science & Data Engineering
Хотя проект является Telegram-ботом, его архитектура напрямую пересекается с задачами работы с данными:
- Data Pipelines & ETL: Бот собирает сырые данные о действиях пользователей (user_actions), структурирует их и сохраняет в реляционную БД для последующей аналитики.
- Работа с метриками: Реализован сбор и подсчет DAU (Daily Active Users) и конверсий через таблицу daily_conversion_counters.
- Асинхронная обработка: Использование asyncio и aiosqlite демонстрирует понимание того, как обрабатывать потоки данных без блокировок.
- Аномалии и безопасность: Благодаря бэкграунду в ИБ, в архитектуре заложены механизмы защиты от спама (rate-limiting) и разграничение прав доступа, что критично при работе с чувствительными данными.
